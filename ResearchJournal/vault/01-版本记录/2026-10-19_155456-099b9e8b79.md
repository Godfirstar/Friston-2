## 改了什么

全部实现锚点均位于 `friston2/knowledge/hybrid_search.py`。

### `hybrid_ranked_search`

**【代码可证】** 执行顺序为：词法候选 → 意图分流 → 可选语义检索 → SQLite 回查与过滤 → RRF → 去重及来源分散。

- 对 `ids` 保序去重，约束输出数量后调用 `ranked_search`。
- `relationship`、`leadership` 意图跳过 dense；已识别人名的 `introduction`、仅指向 `IDENTITY.entity_id` 的 `personality`，以及未识别实体的介绍／性格类问题也跳过 dense。这里是委托旧检索，**没有新增图遍历或关系推理实现**。
- 在 `try` 内通过 `PRAGMA database_list` 取数据库路径，传入 `semantic_search(..., db_file=Path(active_db_file))`。代码意图是避免误用另一数据库的同号片段。
- dense 命中按 ID 回查 `passages`，并 `LEFT JOIN sources`，获取来源类型、路径、URL 与修订信息。
- dense 候选排除 `category == 'relationship'`，应用 `kinds` 限制；人物经历以及部分指定实体意图要求 `ref_id` 属于 `ids`。其他允许保留的非 owner 候选仍需正文包含实体姓名；无实体的概念查询经过 `_concept_definition`。
- 按片段 ID 融合，新增 `fusion_score` 与 `retrieval_channels`，并把 `score` 改为融合分数。

### `_diversified`

**【代码可证】** 使用 `normalize(content)` 去重；来源键依次取 `source_path`、`source_id` 或片段 ID。优先限制同来源片段数量，候选不足时再从暂存结果补足。

这是**带补位的来源分散规则**，不是语义去重，也不是严格的每文件硬上限。

### `main`

**【代码可证】** 新增 `lexical`／`hybrid` 模式。CLI 先调用实体解析器，遇到 `ambiguous` 时提示并返回；检索类型限定为 `profile`、`character`、`event`、`project`。输出包含通道标签、来源路径、行号和截断正文，并提示二次 Wiki 总结尚未经原作核验。

该提示属于风险告知，没有实现自动原作核验或生成答案校验。

## 新技术简介与取舍

**RRF 的直觉：** 同一片段如果在不同检索列表里都排得靠前，就获得更高融合分；无需直接相加量纲不同的原始分数。

本文件的核心公式是：

`RRF(d) = Σ[c 中出现 d] 1 / (60 + rank_c(d))`

公式中的 `60` 来自 `RRF_K`，排名起点来自 `enumerate(..., start=1)`。dense 先过滤，再参与编号，因此使用的是**过滤后列表排名**。`hit['score']` 被记录为 `semantic_similarity`，不直接进入融合公式。

**【代码可证】** 当前融合对词法、语义通道采用相同形式的贡献；先按融合分降序、片段 ID 升序排序，再执行来源分散。

**【推断】** 这一选择减少了直接混合不同评分尺度的校准负担，但舍弃了原始分数差距，效果依赖候选质量与候选截断。融合本身没有神经模型调用；语义检索底层使用什么模型、相似度算法和索引，当前材料未展示。

| 方案                             | 证据状态              | 取舍                            |
| ------------------------------ | ----------------- | ----------------------------- |
| 保留词法检索                         | 本次继续调用，并提供 CLI 模式 | 复用既有规则；抽象表达的召回能力仍待评估          |
| 词法＋语义＋RRF                      | 本次新增封装可见          | 可融合不同排名；不能把融合分当作事实置信度         |
| 神经 Reranker                    | 历史讨论中的计划；本次未见调用   | 可进一步评估问题与候选的匹配，但需要另行确认模型与运行开销 |
| GraphRAG Lite／Agentic RAG Lite | 历史讨论中的后续方向        | 本次没有相关增量，不能记为已完成或已决定放弃        |

## 潜在问题与回归风险

- **来源字段不是可信度检查。** 注释强调来源与类型检查，但可见 dense 过滤没有依据 `source_type`、`revision` 或原作核验状态拒绝候选。`LEFT JOIN` 也允许来源字段缺失。保留数据库记录不能证明其内容为正史；这些过滤同样不能代替生成阶段约束。
- **降级范围有限。** `try` 包含数据库路径读取与 `semantic_search` 调用，只捕获列出的异常。顶层导入失败、未被列入的 SQLite 异常，以及 `try` 外的命中 ID 转换、回查和过滤错误，不受这一兜底完整覆盖。
- **回退不等于原结果不变。** 跳过 dense 或捕获异常后，返回的是 `_diversified(lexical, limit)`。它与 CLI 直接请求 `top_k` 条词法结果可能不同；“安全退回原检索”的日志不能作为结果等价或安全性验收结论。
- **同库路径不等于索引一致。** 传入当前数据库路径体现了隔离意图，但本文件未见索引与数据库修订绑定校验。数据库更新后同号片段、失效索引，以及内存数据库／附加数据库情形仍待人工确认。
- **分数契约与可观测性存在差异。** 融合路径覆盖 `score`，跳过／异常回退路径则保留原字段，下游阈值不可直接假设通用。`combined.setdefault` 优先保留词法行，重合片段可能丢失 dense 新增的 `semantic_similarity`。CLI 对缺少融合分的结果显示 `RRF=0.00000`，实际含义是未计算该字段，不应记录为测得零分。
- **来源分散可能改变证据呈现。** 同源上限可被补位突破，补位后结果未必按融合分单调排列。归一化正文相同的跨来源片段只保留先遇到的记录，可能丢失其他出处；来源缺失时按片段 ID 分组，也无法真正限制同一文档。
- **实体约束依赖上游契约。** CLI 会拒绝歧义，但直接调用 `hybrid_ranked_search` 不会自行解析或验证 `ids`。空实体的 `general`／`experience` 查询仍可能进入 dense；严格 owner 过滤与正文全名匹配又可能漏掉代称、别名或跨文档证据。影响均未测量。
