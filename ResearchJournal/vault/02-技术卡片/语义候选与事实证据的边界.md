# 语义候选与事实证据的边界


## 2026-10-19 · [[01-版本记录/2026-10-19_155456-099b9e8b79]]

语义相似度用于发现候选；人物归属、来源和真实性需要各自的证据。

本次 `hybrid_search.py::hybrid_ranked_search` 用 dense 命中 ID 回查 SQLite，再检查类别、owner 与部分正文条件。但读取 `source_type`、`revision` 不等于检查可信度，也不能证明索引与数据库同步。

可迁移原则：分别记录相关性、来源追溯与事实核验状态，不用融合分替代后两者。

### 2026-10-19 · [[01-版本记录/2026-10-19_174844-f1bf76d793]]

本轮补充：`friston2/knowledge/retrieve_lore.py` 将非双人物关系问题的段落召回入口改为 `hybrid_ranked_search`，并向成功加入的来源传递 `retrieval_channels` 与 `fusion_score`。前者缺失时默认 `['lexical']`，后者缺失时为 `None`；默认值不是实际通道的独立证明，融合分数也不是事实可信度。

`friston2/skills/npc.py` 同时让已有 `sources` 阻止 `ordinary_chat` 标志成立。这改善了检索结果与对话分流之间的衔接，但不能单凭该条件证明最终回答忠于来源。

本轮未提供混合检索内部实现或质量数据，不能由函数名推定 RRF、神经重排器或事实正确率提升。复习时记住：候选说明“值得查看”，原始段落及其适用范围才用于支持事实。
