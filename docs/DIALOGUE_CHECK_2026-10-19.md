# Friston-3 对话修改与验证记录

> 历史记录说明：本文件保留较早一次工作的陈述。后续核对发现，其中旧 tests.replay_dialogue、31项测试源码及旧重放JSON未随当前目录保留，不能独立复核。当前实现和新测试结果见 [DIALOGUE_REPAIR_2026-10-19.md](DIALOGUE_REPAIR_2026-10-19.md)；新结果不追认为旧验收。

## 结论与范围

对话身份已从自创 Friston-2 改成原作 Friston-3（自称 Friston），知识库说话人绑定 `wiki:char_4093_frston`。原 Friston-2 的同人偏好、二号机别名和关系注入已撤下。现有 Python 包名和项目文件夹保留，避免破坏入口与导入。

“查资料感”有两层原因：自创角色缺少可继承的原作关系；旧流程又在生成校验失败后直接朗读人物简介。另有无关历史污染、短故事标题被当人名、代词形式交情漏检和概念材料错类。只换显示名无法解决这些问题。

角色锚点根据游戏干员档案和语音的社区数据镜像核对；正文材料仍由指定的 `arknights_lore_wiki` 提供。Wiki 自称 LLM 总结，不能整体视为游戏原文。来源及定位见 `data/knowledge/npc_character.json`。口语化短答是有依据的项目转述，不是新增的原作台词。

## 已实现

- 原作自身关系与角色过去使用第一人称，撤下“最喜欢、最信任可露希尔”等自创排名。
- 凯尔希、可露希尔、博士和作业平台同伴的直接关系可从自身节点取得；没有直接往来依据时，不补写相识或断言从未见过。
- 简单自身关系、熟人列表、有限背景记忆及部分人物态度使用有来源的短答；具体剧情和普通闲聊保留模型生成。关键短答会重复，这是当前可靠性与措辞变化之间的明确取舍。
- 仅同话题最近问答进入模型；更换人物后不携带无关旧回答。拒绝草稿不会进入历史，同一批证据至多重新生成一次。
- 代词、隐含自身、关系类型、年限、排名、引号中的关系标签和真实摄影任务分别校验；规则仍不构成完整语义事实核验。
- “天灾是什么”没有合格定义证据时明确缺口，不再用天灾信使简介拼成矿石病解释。
- 世界观库已重建为 `lore_wiki_graph_2`：1,391 个 Wiki 来源、3,199 个实体、7,242 条关系；没有旧自创身份或项目来源注入。

## 仍未完成的验收

- 2B 模型在开放话题中的原作事实、指代和长对话自然度仍不稳定；本次解决了关键身份与关系入口，没有证明任意自由生成都可靠。
- 多数关键关系依靠固定口语化转述维持正确性，表达变化有限。若用户期待所有人物、事件都能自然展开，这次结果尚不能算完全达到。
- 通用概念定义覆盖仍有缺口，“天灾”目前会说明缺证；未额外伪造一份世界观全知库。
- 没有启动真实摄像头验收，也没有测试尚未接入的机械臂。原摄影功能边界保留。

退出旧进程后照常运行 `python main.py` 即使用新身份，本机知识库已完成重建。
